# varve-sh/homebrew-tap

Homebrew formulae for [varve](https://github.com/varve-sh/varve) — decision
memory for AI coding agents.

```bash
brew install varve-sh/tap/varve
```

## Contents

| Formula | Status |
|---|---|
| `varve` | Current. Written by GoReleaser on each release of `varve-sh/varve`. |
| `memtrace` | **Deprecated.** varve was called memtrace until 2026-07-29. Pinned at v1.5.4 (MIT). Installs and upgrades still work — GitHub redirects the old release URLs — but it receives no new versions. |

`Formula/varve.rb` is generated. Do not hand-edit it; it is overwritten on every
release. `Formula/memtrace.rb` is no longer generated by anything and is
hand-maintained.

## Migrating from memtrace

```bash
brew uninstall memtrace
brew install varve-sh/tap/varve
```

Your memory store is not touched by either command. varve reads a pre-rename
store at `.memtrace/memtrace.db` in place and tells you so; `varve store move`
relocates it to `.varve/varve.db` when you ask it to.

## Cutover

After the first **stable** varve release publishes `Formula/varve.rb`:

```bash
git pull
./scripts/cutover.sh
git push origin main
```

It removes `Formula/memtrace.rb` and adds `formula_renames.json`, so Homebrew
migrates `memtrace` users to `varve` on `brew upgrade`.

The script **refuses to run** until `Formula/varve.rb` exists, because that
ordering is the part that is easy to get wrong: the rename map without its target
makes `brew install varve-sh/tap/memtrace` resolve to a formula that is not
there, breaking the only thing this tap currently does. Prereleases do not
publish a formula (`skip_upload: auto`), so the trigger is a stable tag.
